# STANDARDS.md

## Request path
- **Best-effort notifications**: `notifyBestEffort` (lib/tickets.ts) never rejects and logs `<action> notify ticket <id>:`. Add awaits it (the new id is returned); Close/Reopen fire it with `void` after the write (long-lived `next start` process, 5s fetch timeout bounds the dangling promise). Any new unawaited send must go through a never-rejecting wrapper like this one.
- **One-call transitions**: Close/Reopen with no response is one conditional `update ... in("status", from) ... select("ticketdate, description")` (`moveTicket`); 0 rows triggers a single follow-up read to tell `state` from `notfound`. With a response, `move()` first reads the ticket (`loadTicket` + `from.includes`) so a stale tab is refused before anything is written, then inserts the message, then updates; a lost race deletes the message again (the delete's `{error}` is checked and logged as `move ticket <id> response <msgId> cleanup failed: <msg>`). A message insert that fails with FK 23503 (ticket gone since the read) is `notfound`. Any new transition keeps this shape: no read on the no-response path, never a write that a stale state would have to undo.

## UI
- **Re-keyed forms**: server-rendered forms that redirect to their own URL are keyed with a per-render stamp (`Date.now()`) so the redirect remounts them and clears inputs and any client state (e.g. SubmitButton `clicked`).
- **Submit buttons**: ticket forms use `app/tickets/submit-button.tsx` (`useFormStatus`, disabled while pending, "Saving…" on the clicked button only). Close/Reopen is the exception in effect: the optimistic flip unmounts the clicked button, so while the flip is unconfirmed the control that replaced it renders the "Saving…" label (disabled by the pending form).
- **Optimistic status**: `app/tickets/optimistic-status.tsx` (`useOptimistic`; a provider around each row so the badge cell and the button cell share one value) flips the status badge and which of Close/Reopen show the moment a button is clicked. It covers only those two; the Edit disclosure follows the server render. There is no revert code: React drops the flip when the form action settles, so the server-rendered status (the redirect's fresh data, or the unchanged row after `?error=`) is the revert. A closure `formAction` has no no-JS / pre-hydration POST fallback (accepted, see the `ponytail:` comment). Node tests shim `useOptimistic`, so the real flip and revert were checked in a browser only (Playwright against `next start` with a local stub of auth + PostgREST); redo that check when this file changes.

## Tests
- **Local runs in a symlinked worktree**: do not run `pnpm build` / `pnpm test` where `node_modules` is a symlink to another checkout; pnpm 11's deps check reinstalls and purges the shared directory. Run `node_modules/.bin/next build` and `node_modules/.bin/tsx --test <the file list in package.json "test">` directly, with no `.env.local` (never against production).
- **useFormStatus / useOptimistic shim**: react-dom 18.3 has no `useFormStatus` (and react 18.3 no `useOptimistic`) under plain node; render tests assign `createRequire(import.meta.url)("react-dom").useFormStatus` (see tests/tickets/page.test.mjs, tests/cases/convert.test.mjs).
